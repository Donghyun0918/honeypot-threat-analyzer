공격자를 유인해 기록하는 것까지는 오픈소스가 해준다. 남는 것은 해석이다. 허니팟이 쌓은 영문 원시 이벤트를 규칙 기반 분류와 한국어 LLM 해설을 거쳐, 전담 보안 인력이 없는 조직도 그대로 읽고 바로 조치할 수 있는 형태로 바꾼다.

실제 파이프라인이 만드는 필드 구성이다. 위험도는 LLM 이 아니라 MITRE 점수에서 계산한다 — 측정해보니 모델이 고위험을 낮게 매겼기 때문이다.

문제

수집은 이미 해결된 문제다

T-Pot 은 허니팟 25종을 묶어 로그를 쌓아준다. 그런데 남는 것은 cowrie.login.failed 같은 영문 원시 이벤트뿐이고, 이걸 "무슨 일이 있었고 뭘 해야 하나"로 옮기려면 허니팟별 스키마와 MITRE ATT&CK 를 이미 알아야 한다.

대부분의 조직에는 그 사람이 없다. 그래서 로그는 쌓이기만 한다.

이 프로젝트는 T-Pot 본체를 수정하지 않는다. Elasticsearch 를 읽어 자기 인덱스에만 쓰는 사이드카 4종을 얹었다. 업스트림 업데이트와 충돌하지 않고, 한 단계가 실패해도 이전 단계는 그대로 남는다.

모델은 라벨을 뒤집지 못한다. 규칙이 기준선이고 모델은 자기 판단만 남겨, 어긋난 782건이 사람이 볼 큐로 떠오른다. AI 가 틀려도 분류가 무너지지 않는 구조다.

측정해서 알게 된 것

재보지 않았으면 그대로 틀렸을 것들

이 프로젝트의 결과물 절반은 "무엇이 되는가"가 아니라 "무엇이 왜 안 되는가"다. 전부 실측에서 나왔다.

위험도는 LLM 에게 맡길 일이 아니었다

3B 모델이 고위험 10건을 10건 다 낮게 매겼다. 프롬프트를 고쳐도 같았고 7.8B 로 올려도 2/10 에 그쳤다. 능력 한계이므로 점수에서 계산하도록 회수했다.

10/10 실패 → 점수 파생

같은 이야기를 4만 번 쓰고 있었다

고위험 45,075건이 실제로는 74개 공격 패턴이고, 상위 2개(둘 다 포트 445)가 89.8% 를 덮는다. 패턴당 한 번만 해설하도록 고쳤다.

31.8일 → 75분

모델 성능이 아니라 측정이 틀렸다

평가셋을 학습과 다른 인코더로 만들어 카테고리 코드가 밀렸다. 20만 행 중 6만 행이 모델이 배운 적 없는 코드로 들어가 성능이 낮게 나왔다.

92.5% → 실제 99.9%

게이트는 최적화가 아니라 성립 조건이다

위협 점수 70 이상만 통과시키는 필터가 95.6% 를 막는다. 없으면 100만 건이 전부 추론으로 들어가 725일이 걸린다.
